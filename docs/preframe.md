# Preframe בתוך האתר

Preframe היא התוכנה להכנה להפקה ממשפחת פריימליין. הקוד שלה נמצא בתיקייה הזאת:

```
~/Documents/preproduction-suite
```

המסמך המלא שלה הוא `docs/accounts.md` שם. כאן כתוב רק מה שנוגע לאתר.

## מה האתר עושה בשבילה

החליט דניאל, ב־15 באוקטובר 2026: כל ההתחברות והצד שרת של Preframe עוברים דרך האתר הזה, וכל המשתנים יושבים רק בוורסל.

- **הקוד:** קטע אחד בתוך `api/paypal.ts`, בין `// >>> PREFRAME` ל־`// <<< PREFRAME`. פונקציה חדשה אי אפשר להוסיף, כי התקרה של שתים־עשרה פונקציות מלאה, וייבוא קבצים מקומיים בתוך `api/` אסור (ההערה בראש הקובץ).
- **הכתובת:** `POST /api/paypal?action=preframe`, עם `op` בגוף הבקשה. היא עונה לכל מקור, כי האסימון עובר בכותרת ולא בעוגיות. הבקשה לא עוברת דרך בדיקת השיטה, מתג התחזוקה ושומרי העלות של שאר הפעולות.
- **בסיס הנתונים:** פיירסטור בפרויקט פיירבייס נפרד, `preframe-1c256`. המפתח במשתנה הסביבה `PREFRAME_FIREBASE_SERVICE_ACCOUNT`. הוא נפתח כאפליקציה שנייה בשם `preframe`. בגלל זה `getFirebase` בוחרת את האפליקציה של פריימליין לפי השם `[DEFAULT]` ולא את הראשונה ברשימה. מפתח של פרויקט אחר נדחה.
- **ההתחברות:** חשבון פריימליין. האסימון נבדק באפליקציה של פריימליין, כמו בכל האתר.
- **מי קורא לה:** התוכנה, ושני השרתים של Preframe בקלאודפלייר, שרת הסנכרון ושרת התמונות. השרתים לא מחזיקים שום מפתח. הם שולחים את אסימון ההתחברות של המשתמש עצמו.

## בדיקות ופיתוח

```bash
npm run test:preframe
```

הבדיקות גוזרות את הקטע מהקובץ לפי הסימנים, ומריצות אותו מול בסיס נתונים בזיכרון. העותק שנגזר נכתב ל־`tests/.gen/`, שלא נכנס לגרסה.

```bash
npm run preframe:dev
```

זה שרת החשבונות במחשב, לפיתוח של Preframe: אותו קטע, בסיס נתונים בזיכרון שמתחיל ריק, ואסימוני פיתוח במקום התחברות. הוא לא עולה לשום מקום.

## עוד לא בנוי

- מסך בפאנל הניהול להענקת מנוי של Preframe. הפונקציה `pfGrant` קיימת, וצריך לשים אותה מאחורי בדיקת המנהל הקיימת.
- גרסת הדפדפן של Preframe בתוך האתר. הבנייה שלה שוקלת בערך שבעים ותשעה מגה, ולכן הקבצים הכבדים צריכים לבוא מקלאודפלייר ולא מוורסל.
